# HW7 — Progressive Web App (built on HW6: Firebase Auth & TanStack Query)

React shop built with React Router, TanStack Query, Firebase Auth and the [DummyJSON](https://dummyjson.com) products API.

Live demo: https://reactroutes-seven.vercel.app

## Setup
```bash
npm install
cp .env.example .env.local
npm run dev
```
Fill `.env.local` with your Firebase web app config. In Firebase Console → Authentication enable **Email/Password** and **Google**, and add your deploy domain to **Authorized domains**.

## Routes
| Route | Page |
|---|---|
| `/` | Home |
| `/about` | About |
| `/products` | Products list (search, filters, sort, pagination in URL) |
| `/products/:id` | Product details + delete |
| `/dashboard` | Dashboard |
| `/login` | Email/password login + Google sign-in (guests only) |
| `/signup` | Email, password, confirm password with validation (guests only) |
| `/profile` | Protected: email, UID, logout |
| `/offline` | Offline page with Retry connection |
| `*` | 404 |

Unauthenticated users opening `/profile` are redirected to `/login` and sent back after login. The NavBar shows Login/Signup or Profile/Logout depending on auth state.

## Authentication
- `src/firebase.js` initializes Firebase from `VITE_` env variables and sets `browserLocalPersistence`, so the session survives a refresh.
- `src/services/authService.js` wraps signup, login, Google sign-in, logout, `onAuthStateChanged` and error messages.
- `src/context/AuthContext.jsx` exposes `AuthProvider` and `useAuth()` with `user`, `loading`, `error` and the auth actions.
- `src/routes/ProtectedRoute.jsx` contains `ProtectedRoute` and `GuestRoute`.

## Caching strategy
Server data is cached with TanStack Query (`src/hooks/useProducts.js`).

- Query keys: `['products']` for the product list (used by Products and Dashboard), `['products', id]` for a single product.
- `staleTime` is 5 minutes: cached data is served instantly and not refetched during that time. After that it is revalidated in the background on mount or window focus.
- `gcTime` is 10 minutes: unused cache entries are removed after that.
- Invalidation: after a product is deleted (`useDeleteProduct`), every query starting with `['products']` is invalidated, so the list, dashboard and details are refetched. DummyJSON only simulates writes, so the deleted product reappears after the refetch.
- Outdated requests: TanStack Query passes an `AbortSignal` to the fetch functions and stores results per query key, so an older response can never overwrite a newer one.
- Loading, error and empty states are handled on Products, Product details and Dashboard.

## PWA
The app is installable and works offline. The service worker is hand-written (no Workbox).

### Manifest & installation
- `public/manifest.json`: name, short_name, start_url, scope, `display: "standalone"`, theme/background colors.
- Icons in `public/icons`: 192×192, 512×512, maskable 512×512, apple-touch-icon. Generated by `node scripts/generate-icons.mjs`.
- Linked in `index.html` together with `theme-color` and Apple meta tags.

### Service worker lifecycle (`src/sw.js`)
- The `serviceWorker()` plugin in `vite.config.js` builds `/sw.js` from `src/sw.js` and injects the list of every built JS/CSS file, `index.html`, icons, manifest and `offline.html`, plus a version hash of the build.
- **install**: pre-caches that app shell into `shop-precache-<version>`.
- **activate**: deletes caches from older versions, remembers the open pages, `clients.claim()`.
- **fetch**: routes requests to the strategies below.
- **Updates**: a new worker waits instead of taking over. `src/pwa/serviceWorker.js` detects it and `UpdateBanner` shows *"A new version is available — Update now"*. Clicking sends `SKIP_WAITING`; on `controllerchange` the page reloads with the new version. `sw.js` is served with `no-cache` (`vercel.json`) and registered with `updateViaCache: 'none'`, and updates are checked hourly and when the app becomes visible, so no one has to clear storage.

### Runtime caching
| Requests | Strategy | Cache | Limits |
|---|---|---|---|
| App shell (built JS/CSS, icons, offline page) | Pre-cache | `shop-precache-<version>` | replaced every deploy |
| Images, icons, fonts (incl. product images from the CDN) | **Cache-first** | `shop-static-v1` | 150 entries |
| Public DummyJSON `/products` list & details | **Network-first** (4 s timeout) | `shop-api-v1` | 60 entries, 7 days |
| Page navigations | Network-first → app shell for visited pages → `offline.html` | `shop-pages-v1` | 50 entries |

- When the API answer comes from the cache, the worker adds `X-SW-From-Cache` / `X-SW-Cached-At` headers; `services/service.js` reads them and pages show *"Showing cached data saved …"*.
- TanStack Query uses `networkMode: 'offlineFirst'` so requests still reach the service worker offline, and `refetchOnReconnect: 'always'` to replace cached data when the connection returns.
- A product page also works offline if only the product list was cached (it is used as `initialData`).
- Not cached: anything that is not GET (e.g. delete), Firebase Auth / Google requests and tokens, and every request not listed above. Firebase keeps its own session in IndexedDB.
- Failed requests never crash the app: offline API calls return a 503 that the UI shows as an offline screen, missing images get a placeholder, and an `ErrorBoundary` catches page errors.

### Offline
- `/offline` route (`pages/Offline.jsx`) and a self-contained `public/offline.html` that the worker serves when a page can't be loaded offline. Both have a **Retry connection** button that makes a real network request (not just `navigator.onLine`).
- An Online/Offline indicator sits in the navbar, with a banner while offline.
- Pages visited before (and their cached data) open offline; normal behaviour returns when the connection does.

### Testing locally
The service worker only runs in production builds:
```bash
npm run build && npm run preview
```
DevTools → Application shows the manifest, service worker and caches; Network → Offline simulates no connection.

### Mobile
Works from 320px wide, in portrait and landscape: hamburger menu, 44px touch targets, 16px inputs (no iOS zoom), stacked filters, 2-column product grid, single-column details/dashboard, no horizontal scrolling, safe-area insets for the installed app.

## Structure
```
src/
  firebase.js            Firebase init
  context/AuthContext.jsx
  routes/ProtectedRoute.jsx
  services/service.js    API requests
  services/authService.js
  hooks/useProducts.js   TanStack Query hooks
  hooks/useOnlineStatus.js
  pwa/serviceWorker.js   SW registration, update handling, connectivity check
  sw.js                  service worker template
  layouts/  components/  pages/  styles/
```

## Deploy
Vercel: import the repo, add the `VITE_FIREBASE_*` variables in project settings (uses `vercel.json` for SPA rewrites).
Netlify: build `npm run build`, publish `dist`, add the same env variables (uses `public/_redirects`).
